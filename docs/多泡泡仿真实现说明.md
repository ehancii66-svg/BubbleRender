# BubbleRender 多泡泡仿真实现说明

## 1. 文档目的

本文记录 BubbleRender Windows 实验端中双泡、三泡及后续多泡泡交互仿真的设计过程、已完成内容、关键原理和当前限制。

Windows 端的定位不是完整复现某一种离线流体算法，而是建立一套能够实时运行、视觉连续，并可迁移到 HarmonyOS 的轻量泡泡交互框架。当前实现重点解决以下问题：

- 泡泡在风场和外力下持续运动；
- 泡泡接近时提前产生柔软形变，而不是作为刚性球碰撞；
- 接触后形成稳定的接触圆和共享膜；
- 一个泡泡可以同时参与多条接触关系；
- 自由状态、接触状态和成熟共享膜之间不切换整套主体几何；
- 接触过程中的位置、速度、法线、折射和薄膜颜色尽量保持连续；
- 为后续用户动态生成任意数量泡泡、Plateau junction、膜排液、融合和破裂预留结构。

当前主要实现位于：

- `windows/main.cpp`
- `windows/shader/shader_refraction.h`
- `windows/simulation/vortex_sheet.*`

## 2. 实现演进

### 2.1 早期的球体碰撞与吸附

最初版本把泡泡近似为球心和半径，并在较大的距离范围内启动吸引。早期接触范围曾使用约 `0.35 * minRadius` 的 margin，并且更远处就开始毛细吸引。这会导致两个泡泡视觉上还未接触就明显吸附。

后续将近场范围缩小为约：

```text
nearRange = 0.08 * minRadius
contactEpsilon = 0.012 * minRadius
```

其中 `nearRange` 只负责预接触柔化，真正建立 bonded contact 的距离接近：

```text
distance <= radiusA + radiusB + contactEpsilon
```

### 2.2 独立球壳与 assembly 切换问题

早期接触后会从两个完整球壳切换到一份 fused/assembly 几何。即使使用 alpha 交叉淡入淡出，在切换帧仍可能出现：

- 轮廓位置突然变化；
- 折射采样半径发生改变；
- 法线与高光跳变；
- 中间透明区域变黑；
- 薄膜干涉颜色发生突变。

根本原因是自由状态和接触状态使用了不同的几何参数化。透明折射对深度、法线、绘制顺序和背景采样非常敏感，因此普通 alpha 淡入淡出不能从根本上解决问题。

当前版本已经禁用主体的 fused assembly 替换路径。每个泡泡从创建到接触后始终保留自己的持久球壳 Model。

### 2.3 半径双重缩放问题

旧实现中曾出现球壳顶点已经使用实际半径，同时 Model Matrix 又按实际半径缩放的情况，造成视觉半径与碰撞半径不一致。

现在统一约定为：

- 球壳顶点使用单位半径；
- Model Matrix 使用泡泡真实半径缩放；
- 碰撞、接触圆和渲染均使用同一个 `bubble.radius`。

### 2.4 共享膜颜色跳变

早期共享膜会直接修改几十纳米的膜厚，并显著降低 alpha。这会导致接触瞬间干涉色突然变化。

当前版本优先保证视觉连续性：

- 泡泡壳体和共享膜渲染基本保持 `thicknessScale = 1.0`；
- `pair.filmThickness` 仍作为排液、融合和未来破裂的状态变量；
- 该状态暂未直接大幅驱动干涉颜色；
- 共享膜使用较低折射强度和环境反射强度，减少透明叠加黑带。

### 2.5 从双泡扩展到三泡和多接触

当前默认场景使用三个泡泡：

```text
Bubble A radius = 0.48
Bubble B radius = 0.44
Bubble C radius = 0.40
```

泡泡由松散三角形位置向更靠近的 home position 移动，能够自然形成多条接触关系。

接触不再只由一个全局双泡状态管理，而是形成 contact graph：

```text
Bubble = 图节点
BubbleContactPair = 图边
```

例如三个泡泡可以同时存在 `AB`、`AC`、`BC` 三条接触边。每条边独立保存接触时间、接触圆、压缩状态和共享膜参数。

## 3. 当前核心数据结构

### 3.1 DisplayBubble

`DisplayBubble` 表示一个拥有独立身份的泡泡，主要状态包括：

- `id`：稳定的泡泡标识；
- `position`、`velocity`：泡泡中心运动状态；
- `radius`、`initialRadius`：当前半径与初始半径；
- `targetVolume`：目标体积；
- `basePosition`：场景中的松弛位置；
- `phase`、`windAmplitude`、`floatAmplitude`：自由漂移参数；
- `filmThickness`：泡泡膜厚状态；
- `surfaceControls`：持久表面控制点；
- `state`：Free、Touch、SharedFilm、NeckForming、Merged 等状态。

当前 `Merged` 表示共享膜已经成熟，不代表两个泡泡已经完成真正的拓扑合并。A、B 仍保持独立身份和独立球壳。

### 3.2 SurfaceControl

每个泡泡当前拥有 26 个低分辨率表面控制点。控制方向来自 `[-1, 0, 1]^3` 中除原点外的 26 个方向。

每个控制点保存：

```cpp
glm::vec3 localDir;
glm::vec3 displacement;
glm::vec3 velocity;
```

含义为：

- `localDir`：控制点位于单位球面的方向；
- `displacement`：相对于自由球面的持久三维位移；
- `velocity`：该局部表面的形变速度。

这使表面形变具有记忆、惯性和恢复过程，而不是每帧重新用公式直接生成一个静态形状。

### 3.3 BubbleContactPair

每一对候选或已接触泡泡拥有一条 `BubbleContactPair`，主要保存：

- `candidate`：已经进入近场；
- `bonded`：已经建立持久共享膜关系；
- `contactActivation`：连续接触激活强度；
- `contactTime`：接触历史时间；
- `contactRadius`、`contactRadiusVelocity`：接触圆半径及其速度；
- `interactionCompression`、`interactionVelocity`：交互压缩程度及其速度；
- `filteredNormal`：滤波后的接触轴；
- `filteredPlaneCenter`：滤波后的接触平面中心；
- `filmThickness`：简化的共享膜排液状态；
- `bridgeStrength`、`geometryBlend`：接触几何成熟程度；
- `state`：Touch、SharedFilm、NeckForming、Merged 等阶段。

## 4. 每帧仿真流程

### 4.1 自由运动

每个泡泡首先受到弱 home pull、低频漂移和速度阻尼：

```text
velocity += (homePull + slowDrift) * dt
velocity *= exp(-damping * dt)
position += velocity * dt
```

这部分是实时演示外力，不是完整 Navier-Stokes 风场。

### 4.2 空间哈希 broad phase

系统通过三维均匀空间哈希寻找可能接近的泡泡对。网格尺寸约为最大泡泡直径的 1.2 倍，只检查当前网格及相邻 26 个网格。

该步骤称为 broad phase，只负责快速生成候选 pair，避免泡泡数量增加后仍对所有泡泡执行完整的 `O(N^2)` 距离检查。

### 4.3 连续接触激活

泡泡表面间距定义为：

```text
gap = distance - (radiusA + radiusB)
```

接触激活强度为：

```text
contactActivation = Smooth01((nearRange - gap) / nearRange)
```

其中 `Smooth01(x) = x^2(3 - 2x)`，输入被限制在 `[0, 1]`。

该值从接近阶段连续增长，并统一驱动：

- 毛细吸引；
- 法向速度阻尼；
- 接触前局部压扁；
- 接触圆初始半径；
- 接触平面和法线滤波；
- 球壳 coverage 裁切；
- 共享膜可见度；
- 表面控制点的局部压缩。

这样不会在 `candidate -> bonded` 的单帧状态切换中突然启动另一套视觉逻辑。

### 4.4 接触圆动力学

`contactRadius` 表示球壳与共享膜相交的圆形边界半径。

接触圆通过弹簧-阻尼系统追踪目标值：

```text
radiusAcceleration =
    stiffness * (targetContactRadius - contactRadius)
    - damping * contactRadiusVelocity
```

当前参数接近临界阻尼，使接触圆快速增长但尽量避免过冲回弹。

接触圆增大后，两个泡泡的目标中心距离由几何关系反推：

```text
targetDistance =
    sqrt(radiusA^2 - contactRadius^2)
    + sqrt(radiusB^2 - contactRadius^2)
```

当 `contactRadius = 0` 时，目标距离就是 `radiusA + radiusB`。接触圆越大，两个中心允许靠得越近，但相向球冠会被裁掉，不是两个完整球体直接穿透。

### 4.5 多接触位置约束

系统每帧执行 6 次 contact graph 位置约束迭代。每条接触边根据当前距离与目标距离修正两个泡泡中心。

多次迭代的作用是让 `AB`、`AC`、`BC` 等约束共同收敛。如果只处理一次，后处理的 contact 可能破坏前一个 contact 的结果。

多接触形变还会按照活跃接触数量进行分摊，避免一个泡泡同时接触多个邻居时形变强度简单相加而失控。

### 4.6 接触动量转移

早期版本在接触时使用过强法向阻尼，导致球心先停住，表面形变和接触圆随后才增长，视觉上出现“停一下”。

当前版本降低球心法向阻尼，并把被吸收的靠近速度转移到：

```text
contactRadiusVelocity
interactionVelocity
```

因此靠近动量被拆分为：

```text
继续推动泡泡中心靠近
+ 驱动接触圆扩大
+ 驱动局部表面压缩
```

第一次建立 bonded contact 时还会继承入射速度，使共享膜和局部形变在接触首帧就开始发展。

为避免解决停顿后又产生明显软回弹，冲击压缩被限制在成熟 bonded 压缩附近，接触圆使用更强阻尼进入稳定值。

### 4.7 持久表面动力学

每帧首先为每个 SurfaceControl 生成自由振荡目标，然后聚合该泡泡参与的所有 contact。

接触方向内部使用 `capMask`，接触圆附近使用 `rimMask`：

```text
contactTarget =
    -contactAxis * compression * capMask
    + radialDirection * bulge * rimMask
```

含义为：

- 接触帽内部沿接触轴向内压缩；
- 接触圆边缘向侧面鼓起；
- 多条 contact 的目标按权重聚合；
- 不再由 pair 更新顺序覆盖表面状态。

控制点使用弹簧-阻尼更新：

```text
acceleration =
    stiffness * (target - displacement)
    - damping * velocity
```

接触区域使用更高刚度和适中的欠阻尼，使表面快速启动但仍保留软膜惯性。

### 4.8 接触区域速度共享

当前版本借鉴 multi-MELP 的 matching-velocity 思想，对两侧接触帽计算表面材料速度：

```text
surfaceVelocity = centerVelocity + controlVelocity * radius
```

随后求质量加权的共享速度，并让两侧接触帽局部趋向该速度。

这并不是把两个泡泡整体锁死，而是让共享膜附近的局部表面一起运动。球心仍可以继续靠近，差异运动被转换为局部压缩速度。

每条 pair 独立计算自己的帽区权重，避免三泡情况下 `AB` 的速度共享误影响 `AC` 接触区域。

## 5. 持久网格生成

每个泡泡拥有一份长期存在的球壳 Model。每帧只更新顶点，不切换到另一套 assembly。

顶点更新包含：

1. 速度方向拉伸；
2. 自由低阶振荡；
3. 26 个持久控制点的球面插值；
4. 所有 contact 的局部压扁和接触环修正；
5. 近似体积补偿；
6. 三角面法线重算。

控制点对渲染顶点的权重近似为：

```text
weight = max(dot(vertexDirection, controlDirection), 0)^8
```

然后归一化插值得到持久位移。

当前仍保留少量解析接触修正，作用是：

- 在控制点弹簧尚未完全响应的最初几帧立即产生小幅形变；
- 让球壳边界可靠贴合接触平面；
- 弥补 26 个控制点空间分辨率不足。

主体形变仍由持久控制点承担，不会回到无状态的纯解析形变。

## 6. 体积处理

当前每个泡泡保存 `targetVolume`，半径会缓慢向目标体积对应的半径恢复。

局部表面压缩后，系统根据控制点平均径向位移进行小范围整体缩放补偿。这只是实时近似，不是严格体积守恒。

后续应使用封闭三角网格体积积分：

```text
V = 1/6 * sum(dot(x_i, cross(x_j, x_k)))
```

再进行一至两次体积投影，以支持更深挤压、动态生成、融合和分裂。

## 7. 接触平面与球壳裁切

每条 pair 保存滤波后的接触轴和接触平面中心：

```text
filteredNormal
filteredPlaneCenter
```

接触平面中心根据 A 泡泡球面与接触圆的几何关系计算：

```text
planeOffsetA = sqrt(radiusA^2 - contactRadius^2)
planeCenter = centerA + normal * planeOffsetA
```

接触 frame 使用指数低通滤波，避免泡泡运动时膜面方向逐帧抖动。

shader 不再使用简单法线夹角 mask，而是根据世界空间接触平面的有符号距离裁切球壳：

```text
signedDistance = dot(worldPosition - planePoint, planeNormal)
```

裁切区域使用 smoothstep 过渡，避免硬边闪烁。

## 8. 共享膜渲染

每条 candidate 或 bonded contact 会绘制一张共享膜。共享膜与球壳使用相同的：

- `contactRadius`；
- `filteredPlaneCenter`；
- `filteredNormal`；
- `contactActivation`。

因此球壳裁切边界和共享膜边界由同一套接触状态驱动。

共享膜采用较低 alpha、折射强度和环境反射强度，减少多个透明 mesh 叠加产生的黑带。

## 9. 弯曲共享膜

旧共享膜接近固定微弯圆盘，不能表现不同大小泡泡之间的压力差。

当前版本根据 Young-Laplace 压力关系使用有符号曲率：

```text
curvature = 1 / radiusA - 1 / radiusB
```

法线方向由 A 指向 B。于是：

- 两泡半径相同时曲率为 0，共享膜退化为平面；
- A 更大时膜向 A 一侧弯曲；
- B 更大时膜向 B 一侧弯曲；
- 即膜总是向半径更大、内部压力更低的泡泡一侧凸出。

共享膜使用解析球冠：

```text
z(rho) = sign(k) *
         (sqrt(R^2 - rho^2) - sqrt(R^2 - contactRadius^2))
```

其中 `R = 1 / abs(k)`。

当 `rho = contactRadius` 时，`z = 0`，所以弯曲膜边界始终位于原接触平面，不会因为增加曲率产生新的位置裂缝。

每条 contact 绘制前动态更新共享膜顶点和法线。曲率被限制在安全范围，避免半径差极大或接触圆过大时出现无效球冠。

## 10. 当前渲染连续性策略

当前连续性分为三层：

### 10.1 状态连续

- `contactActivation` 从近场连续增长；
- candidate 和 bonded 共用同一套接触参数；
- bonded 首帧继承预接触进度和入射速度；
- contact pair 不会因单帧距离抖动立即销毁。

### 10.2 几何连续

- 每个泡泡始终使用同一份持久球壳；
- 接触圆和接触平面连续变化；
- 球壳通过同一平面裁切；
- 共享膜边界使用同一接触圆；
- 不再启用主体 shell/assembly 切换。

### 10.3 渲染连续

- shell 和共享膜暂时保持稳定 thickness scale；
- 共享膜使用柔和 alpha 和较弱折射；
- 接触 frame 进行低通滤波；
- 透明泡泡按距离排序；
- 共享膜关闭背面裁切，并使用 straight alpha composite。

## 11. 与论文方法的关系

当前实现是论文启发的实时近似，不是任何论文算法的完整复现。

### 11.1 2012 Animating Bubble Interactions in a Liquid Foam

借鉴 weighted Voronoi 的邻接图思想。当前使用空间哈希和 contact graph 近似邻接关系，没有构建完整 weighted Voronoi diagram。

### 11.2 2017 Hyperbolic Geometric Flow

借鉴接触后通过连续膜面松弛而不是刚体碰撞形成结构的思想。当前使用接触圆弹簧、位置约束和局部表面弹簧，没有求解 mean-curvature flow。

### 11.3 2022 MELP

借鉴以下思想：

- 每个薄膜区域保持独立身份；
- 全局低成本几何与局部接触结构结合；
- 接触区域使用 matching-velocity 条件；
- 多泡系统通过局部区域耦合形成泡沫网络。

当前没有实现 MELP 的 Eulerian/Lagrangian 双层粒子、SPH 曲面微分、表面活性剂输运、Marangoni 流动和跨区域材料迁移。

### 11.4 2007 Volume Control

借鉴每个泡泡维护目标体积的思想。当前只做几何近似补偿，没有把体积误差写入流体速度散度场。

## 12. 当前限制

### 12.1 尚未形成统一 Plateau border

当前 `AB`、`AC`、`BC` 共享膜仍是独立 contact patch。三张膜在中央可能互相穿过、重复叠加或留下小缝隙。

后续应让三片膜共享同一条局部边界，并按表面张力平衡趋向约 120 度，而不是简单把法线平均成一条光滑表面。

### 12.2 法线边界尚未统一约束

球壳边界与弯曲共享膜边界位置可以对齐，但各自法线独立计算。透明折射中仍可能看到亮环或角度跳变。

物理目标不是让三片膜法线完全相同，而是让三片膜共享边界位置，并形成稳定的 Plateau 夹角。

### 12.3 膜厚不是二维空间场

当前每个 pair 只有一个膜厚标量，无法表示重力排液、局部黑膜、风吹颜色流和接触区域材料交换。

### 12.4 透明多层渲染仍有限

当前仍使用排序、alpha 混合和 FBO 折射。泡泡数量增加后可能出现绘制顺序错误、重复折射和黑带。后续可考虑 weighted blended OIT 或两层 depth peeling。

### 12.5 Shader 每泡最多四个视觉 contact

当前球壳 shader 最多接收四个接触平面。真正多泡沫中一个泡泡可能拥有更多邻居，后续需要 texture buffer、动态裁切网格或批量 contact 数据。

### 12.6 当前 pair 使用 vector 下标

`BubbleContactPair::a/b` 当前主要作为 `g_DisplayBubbles` 下标使用。用户动态删除泡泡后，下标可能失效。

在实现交互生成和删除泡泡前，应把所有 contact 引用改为稳定 `BubbleId` 或带 generation 的 handle。

## 13. 面向动态多泡泡的后续架构

最终目标是用户通过点击、触摸或拖动动态创建泡泡，泡泡数量可变。

推荐结构为：

```text
Bubble Registry
    动态 AddBubble / RemoveBubble

Contact Graph
    每对邻近泡泡的 ContactPatch

Junction Graph
    从局部 contact 三角关系生成 PlateauBorder

Plateau Vertices
    多条 border 的高阶交汇结构
```

Plateau junction 中的“三”表示局部通常由三片膜汇合，不表示整个系统只能存在三个泡泡。任意数量泡泡可以产生任意数量局部三膜 junction。

建议后续顺序：

1. 把泡泡引用改为稳定 `BubbleId`；
2. 增加 `AddBubble()`、`RemoveBubble()` 和 Model 回收池；
3. 保留当前三个泡泡作为默认回归测试场景；
4. 建立显式 ContactPatch 边界环；
5. 让球壳和共享膜复用同一组边界位置；
6. 从 contact graph 的公共邻居中动态生成 PlateauBorder；
7. 对三片膜施加约 120 度表面张力约束；
8. 实现低分辨率膜厚场；
9. 实现严格体积投影；
10. 最后处理膜排液、破裂、真正融合和分裂。

## 15. 当前增量更新：动态泡泡与结构拆分

本轮在多泡泡基础上增加了两个初始交互功能：

- `B`：运行时新增一个交互泡泡。新泡泡会从泡泡团外围生成，带有朝向中心的初速度和少量切向速度，随后自动进入 broad phase 与 contact graph，和已有泡泡形成候选接触、bonded contact、共享膜与局部形变。
- `V`：删除最后一个动态新增的泡泡。默认三泡场景会保留，用作回归观察场景；删除时会同步移除该泡泡相关的 contact pair 和对应渲染 model。

为了让后续继续扩展到用户点击生成泡泡、破裂删除泡泡和任意数量多泡泡，当前实现已经将泡泡身份从 vector 下标推进到稳定 `BubbleId`：

- `DisplayBubble::id` 是稳定身份；
- `BubbleContactPair::a/b` 保存 BubbleId；
- contact pair 在每帧需要访问泡泡时，通过 `ResolveContactPairIndices()` 映射到当前 vector 下标；
- `DisplayBubbleModelSlot` 将 BubbleId 与 OpenGL model 绑定，避免删除或重排泡泡后模型错位。

本轮也继续拆分了代码结构：

- `windows/simulation/display_bubble.h`：保存 `DisplayBubble`、`BubbleContactPair`、`DisplayBubbleModelSlot` 等数据结构；
- `windows/simulation/display_bubble_simulation.h/.cpp`：保存体积/质量、ID 查找、contact pair 创建、broad phase、活跃接触统计和 surface controls 初始化等基础仿真工具；
- `windows/render/contact_geometry.h/.cpp`：保存泡泡 shell、共享膜圆盘、弯曲共享膜等 CPU 侧几何生成逻辑；
- `windows/main.cpp`：仍负责窗口、输入、主循环、渲染 pass 调度，以及当前尚未完全拆出的多泡泡仿真主流程和渲染主流程。

当前版本的 `B/V` 仍是最小可用交互：它证明运行时动态增删泡泡已经能接入现有 contact graph。后续如果要做用户鼠标点击生成泡泡，需要继续补屏幕坐标到世界空间的投射、生成位置避让、数量上限 UI，以及更高容量的 shader contact 数据通道。
